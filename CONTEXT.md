# CONTEXT.md — Video Downloader

Domain language for seams. Names here drive module boundaries — grep the term, find the seam.

## Glossary

- **SourceUrl** — raw string the user pastes (e.g. `https://www.instagram.com/reel/ABC/` or `https://x.com/user/status/123`). Validated, not trusted. Owns normalization (trim) and identity extraction.
- **Shortcode** — post identity taken from SourceUrl: the `([A-Za-z0-9_-]+)` segment after `/p/`, `/reel/`, `/tv/`, the numeric id after `status/`, or the 11-char YouTube video id. Flows everywhere as typed string, not bare regex group.
- **VideoAsset** — resolved domain object: `{ videoUrl, thumbnail?, shortcode, sourceUrl, platform, label?, title?, gif? }`. Created only by **MediaResolver**. Crosses seams by value — the api action returns it whole and **DownloadLink** encodes it; never reconstruct `videoUrl` + `shortcode` separately at call sites. `label` names the option: a quality rung wherever the provider publishes one (`1080p`, Vimeo's `720p`, Facebook's `HD`), absent when the post offers no name at all — **DownloadLink** and the preview then fall back to the option's position; `title` carries the YouTube video title for the preview header; `gif` is `"file"` for a real gif (the resolver saw image/gif or a .gif URL) or `"video"` for an X animated_gif (an mp4 that plays like a gif), and absent otherwise. The resolver owns that distinction because only it sees the content-type; the preview renders `"file"` as an image and `"video"` as an autoplaying clip; copying takes file bytes where the clipboard takes them, else the link (measured: Chrome takes PNG only, GIF and MP4 both fail). The client never sees the content-type, so the flag crosses the seam instead; `platform` is `instagram` | `twitter` | `youtube` | `facebook` | `reddit` | `streamable` | `vimeo` | `tiktok` | `threads` | `dailymotion` | `loom` | `rumble` | `direct` (`direct` = any other link that serves video).
- **MediaResolver** — deep module. Interface: `resolve(sourceUrl, deps?) → Promise<VideoAsset[]>`. Implementation hides: platform detection, SourceUrl validation, IG HTML fetch + `og:video` parse + embed fallback (runs as an Effect program with typed Instagram errors, bridged back to thrown Errors), X syndication fetch + best-variant selection (runs as an Effect program with typed Twitter errors, bridged back to thrown Errors; mp4, else the m3u8 manifest), YouTube anonymous MP4 extraction with IOS→ANDROID fallback (see **YouTube**), Facebook `browser_native_hd/sd_url` extraction with `hd_src`/`sd_src`/`og:video` fallbacks (runs as an Effect program with typed Facebook errors, bridged back to thrown Errors), and Reddit/Streamable/Vimeo/Dailymotion JSON metadata; Rumble watch-page → embed id → embedJS MP4 ladder (RNSC cookie carried across the 307-to-self, one labeled asset per mp4 rung best first, hls-only live answers not downloadable). Wherever a provider publishes a quality ladder (YouTube, Vimeo, Streamable, Dailymotion, Facebook) it resolves to one labeled asset per rung, best first, so the caller picks the quality instead of the resolver guessing; mp4 is preferred within a rung but a manifest-only rung is kept. Otherwise it falls back to a generic catch-all (video content-type resolves the link itself, else the page's `og:video`); the catch-all reads only the head of a page body and refuses a non-page content-type, so a mislabelled file cannot be decoded into a string. Unknown hosts go through **PublicHost** (private ranges refused, redirects re-checked per hop); supported hosts with unrecognized paths fail fast as invalid. Seam is `fetch` (plus injectable `youtube` formats function and `lookup` DNS function). Every network read is pinned to the addresses that lookup approved (PinnedFetch), so a DNS change between the check and the dial cannot redirect the socket to a private host. Adapters: live `fetch`/DNS in prod, in-memory fixtures in tests (two adapters → real seam).
- **YouTube** — deep module. Interface: `getYouTubeFormats(id, deps?) → TubeAsset[]` (playable renditions, best first). Owns the InnerTube session (one anonymous session per process, retries creation on failure): tries the IOS client first, probes the best url with a HEAD, and falls back to ANDROID when a video's urls refuse anonymous playback. Maps streaming data to plain MP4 urls. The client probe and extraction run as an Effect program (FetchDeps plus YouTubeInfo Layers) bridged back to promises, keeping the thrown-Error contract including the unreachable cause. Seam is `getInfo(id, client)` + `fetch` + `lookup` (live Innertube in prod, stubs in tests). The format HEAD probe re-checks every redirect hop and pins its dial to the approved address, so an upstream-supplied url cannot reach a private host.
- **Container** — the file container a video url (and, server-side, its response content-type) actually is: `mp4` | `m3u8` | `mpd` | `webm` | `mov` | `gif`, plus whether that container is a manifest. Owns the one rule both sides need: **Transfer** names the download with it, the preview decides with it whether a `<video>` can play the asset. Client-safe by construction (no imports) — it is read by a route. A manifest is a playlist the browser cannot play without a JS player, so the preview shows a notice and **Transfer** rewrites its relative refs absolute before the download.
- **Transfer** — deep module. Interface: `proxy(videoUrl, stem, deps?) → Response`. Owns streaming, `Content-Disposition` + `Cache-Control`. The flow runs as an Effect program (FetchDeps Layer) bridged back to promises, keeping the thrown-Response contract — including the signed-href 403, the 502s, and the 413s. It re-checks the url through **PublicHost** before fetching (a page can hand us an internal address to fetch) and dials an approved address through **PinnedFetch**; it refuses anything above `MAX_DOWNLOAD_BYTES`, counting the bytes that actually arrive; the signature check that the url came from the resolver lives upstream in **DownloadLink**. Forwards a client byte-range to the upstream and passes a 206 answer straight through (naming and rewriting apply to full files only); advertises `Accept-Ranges` so seeking works. The second argument is a stem (`<platform>-<shortcode>`), not a filename — `proxy` appends the container **Container** reports, derived from the upstream content-type or the url. Bounds the upstream twice: fast-fail on headers, overall deadline past which a stalled stream is cut (inside the function's own wall clock); passes the upstream size through for progress display. A manifest is buffered so its relative segment, `URI="…"` and DASH `BaseURL`/`media`/`initialization` refs can be rewritten absolute — a saved playlist has no base url left to resolve them against.
- **Platforms** — the client-safe platform vocabulary (`PLATFORMS`, `Platform`). Split out of MediaResolver so browser code (the schema in **ResolveQuery**) imports the list without dragging media-resolver's `node:dns`/`node:net` into the client bundle — doing so once made Vite's externalized stub throw during hydration and the form fell back to a native page reload. Must stay dependency-free. Also owns `PLATFORM_HOSTS`, the one host list every platform resolves from: MediaResolver derives its fail-fast list from it, so a platform without hosts is a type error instead of a silent miss.
- **DownloadLink** — deep module. Interface: `toDownloadHref(assets, index?, deps?) → string` and `fromDownloadRequest(url, deps?) → { videoUrl, stem }`. Owns the VideoAsset → download-file round trip: the `url` + `name` param names, the `<platform>-<shortcode>` stem format (suffixed `-1`, `-2` … for X siblings or `-1080p`, `-HD` … for a named option), and the signature that ties both to an expiry. The href carries `e` (expiry) and `s` (HMAC-SHA256 of the length-prefixed url + name + expiry under `DOWNLOAD_SECRET`), so the download route verifies it on any process with no shared store; a bad, altered, unsigned or expired href is a 403. Both routes cross this seam, and the client only follows the href it was handed.
- **Freshness** — the one window (`FRESH_MS`) a resolution stays usable: the client may re-serve a cached hit, and a signed href stays valid, for exactly as long.
- **PublicHost** — the guard that keeps a server-side fetch of a user-supplied link off the private network: `resolvePublicAddresses(url, lookup)` resolves the host, refuses loopback, private, link-local, CGNAT and their IPv4-mapped IPv6 forms, and returns the approved addresses. **MediaResolver** checks the pasted link and every redirect hop; **Transfer** checks the file before streaming it. Seam is `lookup` (Node DNS in prod on Bun, DoH via `dohLookup` on Workers, addresses in tests). `dohLookup` queries both A and AAAA over DNS-over-HTTPS so an AAAA-only host cannot slip past; a TTL-0 rebind between the DoH check and the Worker's fetch stays open because Workers cannot pin a connection outside your own zone (see ADR-0003).
- **PinnedFetch** — dials one of the addresses PublicHost approved while the request still names the original origin in `Host` and TLS SNI. Bun dials the address in the URL, so the checked address goes there and callers follow redirects themselves, re-checking every hop. Fails closed on an empty approval set. Bun-only: Workers has no raw sockets, so the Workers path checks via DoH and fetches without pinning (see ADR-0003).
- **GifConvert** — client-only mp4→gif conversion plus clipboard reps, owned in one place. Interface: `convertMp4ToGif(src) → Blob` (frames on the main thread, gifenc in a worker where available, inline otherwise), `encodeFrames`/`sampleFrames` (one shared palette from spread samples), `blobToDataUrl`, `gifFileReps`/`convertedReps` (bytes where the clipboard takes them, an html image for rich-text apps, the link for chats), `canCopyGif` (feature detection) and `hasWorker` (prefetch gate). The Foldkit home widget drives it through Convert/Copy/Save Commands with conversion state in the Model, so every transition is a tested Story; the worker never loads in tests or on the server.

## Seams

- `MediaResolver ↔ fetch` — local-substitutable, ports & adapters. Tests inject fixture map; prod injects global fetch. One dispatch program serves every resolver off a single FetchDeps Layer: pure URL matching picks the branch, each platform maps its typed failures to the legacy thrown-Error strings, and resolve() provides the Layer and runs the program once.
- `Transfer ↔ fetch` — in-process. Tests inject recorded CDN body.
- `PublicHost ↔ lookup` — local-substitutable. Tests inject address lists; prod resolves real DNS.
- `PinnedFetch ↔ fetch` — in-process. Tests inject a recording fetch; prod dials the approved address.
- `DownloadLink ↔ secret` — production holds `DOWNLOAD_SECRET`; tests inject a fixed one and a fixed clock.

## Non-goals

- No backward-compat shims. Old `validateInstaUrl` / raw `videoUrl` string seams are deleted when replaced.
